## 核心修复代码

```go
// 在下单前插入的检查逻辑
┌───────────────────────────────────────────────────────────┐
│                  checkProfitReduce()                      │
├───────────────────────────────────────────────────────────┤
│                                                           │
│  for each position (long/short):                         │
│    1. 计算盈利百分比                                      │
│    2. 计算目标减仓阶梯                                    │
│    3. 【新增】检查已存在订单 ↓                           │
│                                                           │
│    ┌──────────────────────────────────────────┐          │
│    │  openOrders = GetOpenOrders(symbol)     │          │
│    │                                          │          │
│    │  for each order:                        │          │
│    │    if order.ReduceOnly:                 │          │
│    │      if (side==long && order.Side==SELL)│          │
│    │      or (side==short && order.Side==BUY)│          │
│    │        ✅ Found existing reduce order    │          │
│    │        → skip placing new order         │          │
│    │        → log and continue               │          │
│    └──────────────────────────────────────────┘          │
│                                                           │
│    4. 如果没有已存在订单 → 正常下单                      │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

## 订单方向映射

```
持仓方向 (Position Side)  →  减仓单方向 (Order Side)
────────────────────────────────────────────────────
   LONG  (多头持仓)      →      SELL  (卖出减仓)
   SHORT (空头持仓)      →      BUY   (买入减仓)
```

## 总结

✅ **修复方式**: 在下单前检查是否已存在同方向的 reduce-only 订单  
✅ **修复效果**: 完全避免重复下单，保护持仓不被过度减仓  
✅ **性能影响**: 每次增加 ~100ms API 调用，可接受
