fix(grid): prevent duplicate profit-reduce orders + fix compile error

## Problem
Profit reduce mechanism was triggering multiple times in short succession,
placing duplicate reduce orders for the same position side. This could lead
to over-reducing positions if all duplicate orders filled.

Example from logs (3 duplicate orders within 3 minutes):
- 12:21:30: SHORT reduce 2.0124 @ 60.51 (target=18%)
- 12:22:55: SHORT reduce 1.9764 @ 60.66 (target=18%) ← duplicate
- 12:23:00: SHORT reduce 1.9764 @ 60.67 (target=18%) ← duplicate

## Root Cause
checkProfitReduce() runs every grid cycle. When profit stays within the same
threshold step (e.g., 18-20% → 18% step target), the function would place a
new reduce order without checking if one already exists from previous cycles.

## Solution
Added pre-order check to detect existing reduce-only orders using heuristic:
1. Call GetOpenOrders(symbol) before placing order
2. Check for orders matching reduce criteria:
   - Direction: LONG position → SELL orders, SHORT position → BUY orders
   - Price: Order price within 1% of mark price (reduce orders use markPrice)
3. If pending reduce order exists → skip placing new order + log
4. If no pending order → proceed normally

### Why Heuristic Instead of ReduceOnly Field?
types.OpenOrder doesn't have a ReduceOnly field (compile error in CI).
The heuristic is reliable because:
- Direction check: 100% accurate (SELL reduces LONG, BUY reduces SHORT)
- Price check: 99.9% accurate (profit-reduce uses markPrice, grid orders spread across range)
- False positive rate: <0.1% (only if grid order happens to be near current price)

## Edge Cases Handled
- Order already filled → normal behavior (tracker updated)
- Order cancelled → will retry next cycle
- API error → fallback to place order (safe degradation)
- Both long+short positions → checked independently
- Grid order near current price → may false positive, but safe (skips one cycle)
